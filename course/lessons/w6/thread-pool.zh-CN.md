# W6 · 线程池、Future 与平滑关闭

## 从这里开始

先理解一个任务如何在一个工作线程上运行。线程池只是对执行同类操作的一组线程进行统一管理。

1. 阅读公共的 `ThreadPool::submit` 声明和提供的 CLI 示例。
2. 从一个工作线程开始，提交一个返回值的函数。
3. 使用返回的 `future` 获取这个值；然后提交一个会抛出异常的函数，观察异常如何传递。
4. 添加多个工作线程，并提交几个相互独立的任务。
5. 测试有界队列的背压，再测试队列中仍有任务时的关闭行为。
6. 最后反复测试提交与关闭流程，并运行 Sanitizer。

**可以这样理解：**`submit` 将工作放入队列；工作线程取出并执行它；`future` 将最终结果传回来。平滑关闭会停止接收新任务，并按照课程约定让已经接收的任务执行完毕。


## 目标

在 W5 有界队列的基础上，构建一个可复用、固定大小的 C++17 线程池。本任务重点学习异步结果传递、可调用对象与参数转发、异常传播、背压，以及并发关闭语义。

## API 与语义

构造线程池时，工作线程数和队列容量都必须为正数。

`submit(function, args...)`：

- 接受任意可调用对象和参数
- 支持只能移动的可调用对象和只能移动的参数
- 返回 `std::future<R>`，其中 R 是可调用对象的结果类型
- 将任务异常存入 future；调用 `get()` 时重新抛出异常
- 队列满时施加有界队列的背压
- 关闭开始后拒绝提交

关闭操作：

- 具有幂等性，并可由多个外部线程安全调用
- 为并发的提交与关闭调用建立明确顺序
- 关闭任务队列，并唤醒被阻塞的提交者
- 执行完已经接收并入队的任务
- 返回前等待每个工作线程结束
- 关闭后拒绝提交

析构函数会调用关闭操作。不要分离工作线程。

## 关键并发约定

只有入队操作在关闭操作关闭队列之前完成，任务才算被接收。因关闭而被拒绝的任务，不能被误当作已接收的工作后再静默丢弃。

实现必须为提交与关闭定义一个线性化点。使用生命周期互斥量保护状态检查和入队操作；关闭操作也应获取同一个互斥量，再将线程池标记为已关闭并关闭队列。注意，有界入队可能在持有这个互斥量时阻塞：工作线程必须继续执行已接收的任务，让被阻塞的提交者能够推进；关闭操作不能在尚未完成的提交中途关闭队列。

多个关闭调用者不能在等待同一组 std::thread 对象结束时发生竞争。使用只执行一次的关闭机制，或等效状态机，让每个调用者都等待所有线程的 join 完成。

任务应在队列锁之外执行。用户异常不得终止工作线程；packaged_task 会捕获异常，并将其传递给对应的 future。

## 故障排查

- **CLI 报告 `TODO: implement ThreadPool::submit`。**检查 `include/thread_pool.hpp` 中刻意保留的占位实现。完成提交路径，并跟踪一个返回值的任务经过 `submit`、`worker_loop` 和 `future::get` 的过程，再尝试多个工作线程。
- **只能移动的参数或可调用对象导致拷贝错误。**检查入队的 `std::function<void()>` 捕获了什么。将可调用对象和参数保存在支持移动的任务存储中，并为已有的共享 `packaged_task` 使用可拷贝的包装；重新测试这两类只能移动的情况。
- **抛出异常的任务终止了工作线程，或丢失了异常。**检查工作线程是否执行了 `packaged_task` 包装。异常必须到达该任务的 future，并由 `get` 重新抛出；在抛出异常的任务之后再提交一个成功任务，确认工作线程继续运行。
- **有界提交或关闭始终无法完成。**检查关闭开始时，工作线程是否在仍有已接收任务的情况下停止。让工作线程在队列关闭后继续处理剩余任务，维持提交与关闭的统一顺序，并让每个关闭调用者都等待工作线程的 join 完成。使用一个工作线程和容量为一的队列重新测试。

## 独立编译期与并发原语补课

可选独立 C++17 补课：在网页点击「查知识」，搜索编号或关键词，先预测，再运行固定失败与修复示例，最后解释并迁移到自己的独立练习。示例完整源码及实际命令输出由知识面板提供，不改变本课程工程、前置关系或正式验收。

- **constexpr · constexpr 与编译期断言** — constexpr 函数可以用于常量表达式，但并非每次调用都在编译期执行。static_assert 在编译时检查常量条件，而运行期输入需要另行检查。 加法结果不符合 static_assert 时会在哪个阶段失败？ 给固定容量与类型属性增加可解释的编译期约束。
- **atomic-access · atomic 的显式读写** — std::atomic<T> 本身不可复制；load 读取值，fetch_add 做原子读改写。原子计数不自动保护多个变量的不变量。本实验不证明多线程内存序或无锁算法。 auto copy = atomic_counter 为什么无法复制？ 用 atomic 计数单项指标，同时说明多字段一致性为什么仍可能需要锁。
