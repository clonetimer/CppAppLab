# W7-B · 使用非阻塞 I/O 与 epoll 的多客户端 TCP 聊天

## 从这里开始

在单客户端 Echo 服务器的基础上继续。新的问题是如何协调多个连接，而不阻塞整个服务器。

1. 画出三个客户端连接一个服务器的示意图。每个客户端都有自己的套接字/文件描述符。
2. 先找出 W7-A 服务器在一个客户端很慢时，会阻塞在哪里。
3. 阅读事件循环流程：`epoll_create → epoll_ctl → epoll_wait`。
4. 先实现接收客户端并记录连接状态，再添加广播功能。
5. 添加昵称注册，然后向其他已连接客户端发送一条消息。
6. 测试断开后的清理、慢客户端、部分写入和有界输出队列。

**可以这样理解：**epoll 告诉服务器哪些描述符已经就绪，不会代替你发送消息。服务器仍然拥有每个客户端的状态，并且必须处理部分读取、部分写入和断开连接。


## 目标

完成 W7 的结课项目：使用非阻塞 Linux 套接字和 `epoll` 事件循环的多客户端 TCP 聊天服务器。

W7-A 已介绍阻塞式套接字的生命周期。本任务从单个阻塞连接推进到多个并发连接，不再为每个客户端分配一个操作系统线程。

## 学习顺序

实现最终事件循环之前，按以下顺序学习各个方案：

1. **每连接一个线程：**容易理解，但每个连接都消耗一个线程，而且共享的广播状态需要同步。
2. **非阻塞套接字：**`O_NONBLOCK` 将原本会阻塞的操作转化为 `EAGAIN/EWOULDBLOCK`；应用必须保留状态，并在之后恢复处理。
3. **select/poll：**基于就绪状态的 I/O 多路复用让一个线程管理多个描述符，但 `select` 有描述符集合大小限制，`poll` 则会扫描描述符数组。
4. **epoll：**Linux 的就绪通知机制更适合扩展到较大的描述符集合。本任务使用水平触发的 epoll，并持续处理可读或可写操作，直到返回 `EAGAIN`。

最终交付物是一个 epoll 服务器。前面的模型用于比较学习，不要求分别实现可用于生产环境的版本。

## 聊天协议

服务器接收以换行符分隔的 UTF-8/字节文本命令：

- `NICK <name>\n` 注册昵称。
- `MSG <text>\n` 广播已注册用户的消息。
- `QUIT\n` 断开客户端连接。

服务器广播：

- `* <name> joined\n`
- `<name>: <text>\n`
- `* <name> left\n`

昵称由 1–24 个 ASCII 字母、数字、下划线或连字符组成。连接期间昵称必须唯一。客户端必须先注册，才能发送 `MSG`。

## 架构要求

- 非阻塞 IPv4 监听套接字
- `epoll_create1` 和水平触发的就绪通知
- 使用带 `SOCK_NONBLOCK | SOCK_CLOEXEC` 的 `accept4`
- 一个事件循环线程拥有客户端映射及全部客户端状态
- 每个客户端都有输入缓冲区，用于处理分段到达的行
- 每个客户端都有输出队列，用于处理部分写入
- 允许读取时启用 `EPOLLIN`；只有存在待发送输出时才启用 `EPOLLOUT`
- 通过 `eventfd` 响应其他线程发出的停止请求并唤醒事件循环
- 限制客户端数量、行长度和待发送输出字节数
- 出错时关闭连接，并进行妥善清理

不要因某个客户端而阻塞事件循环。持续读写，直到操作将会阻塞，然后返回 epoll。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/tcp-chat server 9000
```

在多个终端中使用 `nc 127.0.0.1 9000` 建立连接，然后输入 `NICK alice`、`MSG hello` 或 `QUIT`。

## 故障排查

- **发送 `MSG` 后似乎没有反应。**检查是否已注册，以及你正在观察哪个客户端。注册两个不同的昵称，每条命令都以换行符结束，并从另一个已注册客户端读取消息：聊天协议有意不向发送者回显消息。
- **分段命令失败，或一次写入两条命令时丢失消息。**检查每个客户端的输入缓冲区。保留未完整接收的行，处理每一条完整行，并留下剩余后缀。在测试中，先发送 `NI`，再发送 `CK alice\n`，然后重试一次写入两条完整命令。
- **慢读取客户端阻塞其他客户端，或导致忙循环。**检查待发送输出队列和 epoll 关注的事件标志。部分发送后保留未发送字节，遇到 `EAGAIN/EWOULDBLOCK` 时返回 epoll，并只在仍有待发字节时启用 `EPOLLOUT`。如果某客户端的排队字节数将超过 `max_pending_bytes`，断开该客户端。
- **`request_stop` 让事件循环测试一直等待。**检查停止通道的注册和 `TODO(W7-CHAT-4)`。只修改标志无法唤醒 `epoll_wait`；应向已经注册的 `eventfd` 写入，让循环退出，并在销毁描述符前完成清理。
