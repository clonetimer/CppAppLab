# W1 · 第一个 C++ 程序

## 从这里开始

如果这是你的第一个 C++ 练习，不必急着理解每一行代码。

1. 在工作台中打开 `src/main.cpp`。
2. 找到 `TODO(W1-HELLO)`，添加一条输出语句，使输出严格等于 `Hello, CppAppLab!\n`。
3. 选择**构建**。如果失败，阅读第一条错误信息，记下对应的文件和行号。
4. 选择**运行 / 测试**，将输出与目标进行比较。
5. 只有在程序的行为符合预期后，再选择**正式验收**。

**三个不同的问题：**构建检查源代码能否生成程序；运行检查程序实际做了什么；正式验收检查程序是否满足课程的固定约定，并记录结果。

你只需要编辑**你的任务**中列出的文件。验收测试和参考实现由平台维护。

## 目标

使用 GCC 编译并运行一个小型 C++17 程序。这是你在 CppAppLab 中第一次完成“编辑 → 构建 → 执行 → 验收”的完整流程。

## 你的任务

只编辑：

```text
src/main.cpp
```

让程序准确输出：

```text
Hello, CppAppLab!
```

输出必须以一个换行符结束。随后，程序必须以退出码 0 结束。

## 平台检查什么

运行 `cppapplab check` 时，平台会：

1. 为声明的学员源文件计算指纹。
2. 调用 GCC，启用 C++17 和警告选项。
3. 在较短的时间限制内运行编译生成的可执行文件。
4. 将捕获的输出与预期输出逐字节比较。
5. 记录结果、源代码指纹以及长度受限的日志。

对于这第一个任务，平台不会执行你自己的 CMakeLists.txt，也不会运行学员提供的测试。

## 自行构建

在学员工作区中执行：

```bash
mkdir -p build
g++ -std=c++17 -Wall -Wextra -Wpedantic -g src/main.cpp -o build/hello
./build/hello
```

然后回到 CppAppLab 仓库，运行固定的验收命令：

```bash
./build/cppapplab check "/absolute/path/to/your/hello-workspace"
```

## 理解程序

- `#include <iostream>` 让程序可以使用标准输出流。
- `main` 是程序入口。
- `std::cout` 向标准输出写入文本。
- `\n` 结束当前输出行。
- `return 0` 表示进程成功结束。

## 解释你的结果

验收通过后，用自己的话解释：

1. 编译和运行有什么区别？
2. 为什么平台要精确比较输出，而不只检查进程退出码？
3. 去掉换行符后，会发生什么变化？

## 故障排查

- **构建成功，却没有任何输出。**检查 `src/main.cpp` 中的 `TODO(W1-HELLO)`：初始代码只返回 0。在 `main` 内添加输出语句，然后再次选择**构建**和**运行 / 测试**。
- **添加输出后构建失败。**阅读 `src/main.cpp` 的第一条诊断信息。检查引号、`std::cout` 名称和语句末尾的分号；先修复这一行，再处理后面的错误。
- **问候语看起来正确，但正式验收失败。**将大小写、标点和空格与目标逐一比较，然后检查末尾的换行符。去掉多余的提示或调试输出，结尾只保留一个换行符，并保留表示成功的 `return 0`。

## 验收要求

- [ ] 源代码能以 C++17 标准编译。
- [ ] 可执行文件以退出码 0 结束。
- [ ] 标准输出严格等于 `Hello, CppAppLab!\n`。
- [ ] 验收期间学员源代码没有发生变化。
