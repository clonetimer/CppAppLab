# W8-D4 — 路由器与动态 HTTP 处理器

## 从这里开始

路由器决定由哪个处理器接收请求。它不解析 TCP 字节，也不拥有 socket。

1. 阅读 W8-D2 生成的请求模型。
2. 注册一条精确路由，并向它发送匹配的请求。
3. 注册一个动态处理器，检查方法/路径的精确匹配，以及传给处理器的请求是否保持原样。
4. 在动态路由之后添加静态文件回退处理。
5. 测试未知路由、方法不匹配和格式错误的输入。
6. 跟踪完整处理流程：请求 → 路由器 → 处理器 → 响应 → 序列化器。

**核心理解：**路由器是应用行为的决策表。将网络 I/O 放在路由器之外，就能在不打开 socket 的情况下测试同一个处理器。


## 目标与来源

根据提供的 `快速C++` D4 章节，将动态 HTTP 处理器与静态文件查找分离。沿用课程的递进顺序：请求模型 → Router/StaticFileHandler → 响应模型 → 序列化器。本任务独立于 socket 实现应用处理流程；D5 将集成网络和工作线程池。在本实现过程中，私有 `clonetimer/cpptest` 仓库返回了 404，因此不声称本实现纳入了该仓库的源代码。

## 来自课程的行为要求

Router 同时匹配**方法 + 路径**，而不是只匹配路径。回调类型为 `HttpResponse(const HttpRequest&)`，通过 `std::function` 存储。重复注册相同的方法/路径会替换原有回调。匹配时去掉查询后缀，但传给处理器的是未修改的原始请求，包括目标、首部和消息体。

| 端点 | 响应消息体 | Content-Type |
|---|---|---|
| GET /hello | `Hello from C++ HTTP Server!`，末尾追加 LF | text/plain; charset=utf-8 |
| POST /echo | 原样返回请求消息体的全部字节 | text/plain; charset=utf-8 |
| GET /health | `{"status":"ok"}` | application/json |

未知的动态路径交给现有静态文件处理器。GET / 仍返回 index.html；资源不存在以及不支持的静态请求方法仍沿用 D3 的行为。不引入外部 JSON 库。

## 明确的工程选择

来源材料先介绍精确路由匹配失败后的回退，随后将 `hasPath`/405 作为改进方案讨论。本任务统一采用后者：已知动态路径负责处理方法不匹配和处理器生成的错误。不能仅因为回调返回 404 或请求使用了其他方法，就回退到磁盘查找。

- `Router::handle` 中动态路径不存在时：返回 404。路径已知但方法不匹配时：返回 405，并通过 `Allow` 提供排序、去重后的方法列表。
- 注册时验证非空的 HTTP 方法 token、以斜杠开头且不含查询/片段/反斜杠的可见 ASCII 路径，以及非空回调。替换已有合法条目之前，先拒绝无效输入。
- 存储采用按路径和方法分层的嵌套映射，而不是来源材料中拼接成单一键的方式；匹配仍是精确且区分大小写的。
- `has_route` 和 `has_path` 接收已提取的路径。`handle` 和 `dispatch_request` 仅在查找时去掉查询字符串。
- 处理器异常向上传播到应用边界，由演示 CLI 报告。路由注册必须在提供服务之前完成。并发修改不属于本任务范围。

这些是已明确记录的任务契约细化，并不表示来源示例包含了其中每个细节。

## 实现文件

实现 `router.cpp`、`api_handlers.cpp` 和 `dispatcher.cpp`，并编写十个学员测试。六个公共头文件分别声明模型、解析器、静态处理器、路由器、API 处理器和分发器。已可工作的 D1/D2/D3 实现文件作为脚手架提供，并继续纳入源码指纹。

分发器根据路径是否存在来选择动态处理器，而不是根据返回的状态码。传输字节和按消息体字节计算的 Content-Length 仅由序列化器生成。

## 构建与练习

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
ctest --test-dir build --output-on-failure
printf 'GET /hello?name=Alice HTTP/1.1\r\nHost: localhost\r\n\r\n' | ./build/http-router parse-stdin
printf 'POST /echo HTTP/1.1\r\nHost: localhost\r\nContent-Length: 5\r\n\r\nhello' | ./build/http-router parse-stdin
printf 'GET /health HTTP/1.1\r\nHost: localhost\r\n\r\n' | ./build/http-router parse-stdin
printf 'GET / HTTP/1.1\r\nHost: localhost\r\n\r\n' | ./build/http-router parse-stdin www
```

`parse-stdin [document-root]` 一直读取到 EOF，且只接受一条有大小限制的请求。它使用实际经过加固的 D2 解析器。不完整或格式错误的请求返回 400，进程退出码为 1；尾随的其他请求或超过 16 KiB + 1 MiB 的输入会被拒绝，退出码为 2。解析器仍独立执行自身的首部和消息体限制。404 或 405 等合法的 HTTP 错误响应表示 CLI 执行成功，不是进程失败。

**此 CLI 不绑定 TCP 端口。**通过浏览器或 curl 经 socket 访问的验收属于后续网络服务器任务。本课不添加查询参数解析、URL 解码、模式路由、TLS 和分块传输。静态文件的规范路径与符号链接范围约束仍是 D3 已记录的限制。

## 故障排查

- **`parse-stdin` 一直等待，或 curl 无法连接：**检查所选的 CLI 模式。它一直读取到 EOF，仅接受一条请求，并且不打开监听 socket；使用上面的管道示例，确保 CRLF 定界完整且恰好包含一条请求。
- **动态 404 或错误方法回退到了磁盘：**将路径是否存在、方法是否匹配和返回状态分别检查。重新检查动态 404 与方法不匹配的测试情形；已注册路径始终负责自身的响应。
- **查询字符串破坏了路由或改变了回调收到的请求：**比较用于查找的路径与原始目标。仅为精确查找去掉查询字符串，然后重新运行请求保持不变的测试情形；本任务不支持路径参数匹配。
- **Echo 截断了二进制数据，或请求被过早分发：**检查解析状态、声明的消息体字节数和序列化后的 Content-Length。在修改处理器的响应格式之前，先重新检查不完整消息体和二进制 Echo 的测试情形。
