# W9-A2 · 严格的 HTTP 请求目标与查询解析

## 从这里开始

只解析请求目标一次，并始终保持其含义一致。

1. 从 `/search?q=cpp` 开始，将路径与查询分开。
2. 解码一个经过百分号编码的路径段。
3. 解析重复的查询键，并保留它们的顺序。
4. 拒绝格式错误的百分号转义和不受支持的目标形式。
5. 验证路由使用解析后的规范路径，不会再次解码。
6. 测试编码后的分隔符、点路径段以及有歧义的路径。

**理解模型：**解析和规范化为请求确定唯一的规范含义。后续再次解码可能导致安全漏洞，因为两个组件可能以不同方式解释同一组字节。


## 目标

只解析 HTTP request-target 一次，将其转换为路径和有序的查询参数列表。本阶段为路由和后续安全静态文件任务建立唯一的规范解释。

## 接受的请求目标形式

- 源站形式（Origin-form）：/path/to/resource?key=value
- 星号形式（Asterisk-form）：OPTIONS *

此教学服务器不充当前向代理，因此拒绝 http://host/path 这样的 absolute-form 目标。也拒绝 CONNECT authority-form。

## 解码与规范化策略

- 原始目标必须由可见 ASCII 组成，长度不超过 8 KiB，且不得包含片段、原始空白、控制字节、非 ASCII 字节或反斜杠。
- 路径必须以斜杠开头，长度不超过 4 KiB。
- 百分号转义经过校验后，恰好解码一次。
- 拒绝路径中经过百分号编码的斜杠和反斜杠。字面斜杠仍作为路径段分隔符。
- 解码后拒绝 NUL、控制字节和 DEL。
- 一轮解码后，拒绝单点和双点路径段。解析器不会静默规范化它们。
- 查询字符串限制为 4 KiB、128 个参数，且每个解码后的名称/值不超过 1 KiB。
- 查询参数保留输入顺序和重复名称。允许空值和缺失等号；拒绝空名称和空参数段。
- 加号保留为字面加号。此解析器实现 URI 查询语义，而不是 application/x-www-form-urlencoded 语义。
- 查询的百分号解码允许编码后的斜杠；路径分隔符规则不适用于查询值。

返回的路径已经完成百分号解码。下游路由和文件系统代码不得再次解码。

## 故障排查

通过固定库检查验证 `parse_request_target`；本任务没有监听服务器，也没有独立 CLI。

- **`%252e` 变成了点，或查询字节进入了路径：**检查原始路径/查询的分割，以及解码次数。重新检查双重编码用例；先分割原始目标，再对每个组成部分恰好解码一次。
- **编码后的分隔符在路径中被接受，却在查询中被拒绝：**检查当前验证的是哪个组成部分。重新检查路径中对 `%2F`/`%5C` 的拒绝、解码后的点路径段，以及查询值中允许的编码斜杠。
- **重复键消失，或加号变成空格：**检查有序查询容器和参数分割。重新检查重复名称、字面 `+` 以及含 `=` 的值；保留输入顺序，并在参数的第一个等号处分割。
- **格式错误的转义或不受支持的目标形式被接受：**接受结果前，检查原始字节、方法以及大小限制。重新检查不完整转义、absolute/authority 形式以及 `OPTIONS *`；对于无效目标，该 API 返回 Error，而不是 NeedMoreData。
