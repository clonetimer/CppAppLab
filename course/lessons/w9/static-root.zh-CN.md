# W9-A3 · 将静态文件安全地限制在根目录内

## 从这里开始

目标是提供某个可信目录下的文件，同时避免沿攻击者可控的路径访问。

1. 打开配置的文档根目录，并保存它的目录文件描述符。
2. 通过相对于描述符的查找提供一个普通文件。
3. 尝试包含 `..` 的路径，验证它无法逃出根目录。
4. 在根目录内创建一个指向目录外的符号链接，验证不会跟随它。
5. 测试不存在的文件、目录索引和非 GET 方法。
6. 追踪每个路径组件如何相对于已经打开的目录被打开。

**理解模型：**路径字符串不能证明文件位于文档根目录内。相对于描述符的遍历配合禁止跟随符号链接，才能在文件系统层面强制执行边界。


## 目标

用相对于描述符的文件访问替代路径字符串拼接。文档根目录只打开一次，并以目录文件描述符的形式保留。每个路径组件都相对于一个已经打开的目录描述符解析；绝不跟随符号链接。

## 必须满足的安全属性

- 使用已完成的 W9-A2 解析器解析原始请求目标。不要在文件处理器中再次剥离查询字符串或进行百分号解码。
- 只提供 GET 服务。其他方法返回 405，并携带 Allow: GET。
- 只接受请求目标解析器返回的、已经解码的规范 origin-form 路径。
- 将 / 和以 / 结尾的路径映射到相应目录内的 index.html。
- 拒绝路径内部的空组件、点路径段、反斜杠以及格式错误的请求目标。
- 使用 O_DIRECTORY、O_CLOEXEC 和 O_NOFOLLOW 打开配置的文档根目录一次。在处理器整个生命周期内保持其描述符有效。
- 使用 openat(parent_fd, component, O_RDONLY | O_DIRECTORY | O_CLOEXEC | O_NOFOLLOW) 遍历中间组件。
- 使用 openat(parent_fd, name, O_RDONLY | O_CLOEXEC | O_NOFOLLOW | O_NONBLOCK) 打开最后一个组件。
- 对已打开的描述符使用 fstat，只提供普通文件。O_NONBLOCK 防止打开 FIFO 时在类型检查之前发生阻塞。
- 既根据 fstat 元数据，也在读取过程中执行配置的最大文件大小限制，使文件即便在初始大小检查后增长，也无法突破内存上限。
- 从已经打开的描述符读取字节。绝不要通过重新构造的绝对路径再次打开文件。
- 如果文档根目录在处理器构造后被重命名，仍保持基于描述符的根目录稳定。

此策略拒绝文档根目录下的所有符号链接，包括指向根目录内其他位置的符号链接。这是有意的设计：让第一版安全实现易于审计。文档根目录路径本身是可信配置，且其最后一个组件不得是符号链接。

## 为什么字符串前缀检查不够

词法检查可以拒绝请求字符串中的 ../，但仍可能被符号链接绕过，也可能因路径在检查与打开之间发生变化而被绕过。目录文件描述符配合 openat/O_NOFOLLOW，使每次查找都相对于一个已经打开并验证的目录。中间目录一旦打开，重命名或替换其路径名都不会使该描述符转向其他位置。

## 解释你的设计

1. 为什么处理器必须使用 W9-A2 解码后的路径，而不能再次解码？
2. 为什么必须对每个路径组件使用 O_NOFOLLOW，而不只是最后的文件？
3. 为什么打开中间组件时使用 O_DIRECTORY？
4. 为什么目录文件描述符比拼接文档根目录与请求路径更可靠？
5. 为什么在 fstat 之前打开最后一个组件时，O_NONBLOCK 很有用？
6. 为什么处理器必须在打开描述符后验证 S_ISREG？
7. 为什么必须在读取之前和读取过程中都检查文件大小限制？
8. 为什么打开的目录描述符在路径名被重命名后仍指向原来的目录？
9. 为什么本任务连指向文档根目录内部的符号链接也拒绝？

## 故障排查

固定库检查会创建临时文件树，并直接测试处理器；工作区不提供服务器可执行程序。

- **根目录重命名，或销毁处理器的一个副本后，查找失败：**检查保留的目录描述符的所有权和生命周期。重新检查根目录重命名和共享副本用例；从已打开的根目录解析，而不是重新打开它原来的路径名。
- **符号链接导致提供了根目录外的文件：**检查每个组件相对于描述符的打开操作，不只检查最后的文件。使用禁止跟随链接的遍历，重新检查中间组件和最后组件的符号链接用例；本任务也拒绝指向根目录内部的符号链接。
- **打开 FIFO 时挂起，或提供了超大文件：**检查最终打开标志、`fstat` 类型以及读取大小记账。重新检查非阻塞 FIFO 拒绝用例，以及恰好达到上限/超过上限的文件，在读取前和读取期间都执行字节数限制。
- **编码后的百分号文件名失败，或查询改变了查找结果：**检查已完成的请求目标解析器返回的解码路径。重新检查单次解码和查询隔离用例，将该路径直接交给遍历过程，不要再次剥离或解码。
