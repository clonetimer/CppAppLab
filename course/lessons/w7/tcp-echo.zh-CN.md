# W7-A · TCP/IP 与第一个阻塞式 Echo 服务器

## 从这里开始

先让一个客户端向一个服务器发送一条短消息，再考虑多个客户端。

1. 在回环地址和一个测试端口上启动服务器。
2. 阅读调用流程：`socket → bind → listen → accept`。
3. 连接一个客户端，发送一条短消息。
4. 持续读取，直到收齐预期的完整消息；不要假设一次 `recv` 就能返回全部内容。
5. 重启提供的服务器，再进行第二次 CLI 客户端交互，然后测试客户端断开连接。
6. 之后再检查错误处理、完整写入和描述符清理。

**可以这样理解：**TCP 是可靠的字节流，不是消息队列。在本练习中，服务器会回显收到的每一个字节，直到客户端关闭写入方向（`SHUT_WR`）。换行符没有特殊含义。


## 目标

将 W5 的文件描述符模型扩展到真实网络端点。Linux TCP 套接字也由文件描述符表示：

```text
socket → fd → send/recv → close
```

应用看到的 TCP 是可靠、有序、双向的字节流。TCP **不保留**应用层消息边界：不能保证一次 `send()` 对应一次 `recv()`。

## 学习内容

- IPv4、IP 地址、端口、回环地址和网络字节序
- `socket / bind / listen / accept`
- `connect / send / recv / shutdown / close`
- `sockaddr_in`、`htons`、`htonl`、`inet_pton`
- 阻塞式系统调用和对端 EOF
- 部分发送、EINTR 和 RAII 所有权

服务器绑定 IPv4 地址和端口，开始监听，接收一个客户端，并持续回显字节，直到对端有序关闭写入方向。端口为零时，请求操作系统选择一个可用端口；通过 `TcpEchoServer::port()` 查询实际端口。

## 必须满足的语义

- 验证 IPv4 地址字面量，并要求监听队列长度为正数。
- 使用 `AF_INET` 和 `SOCK_STREAM`。
- 使用 `htons` 转换端口；不要将主机字节序的值直接写入 `sin_port`。
- 处理被中断的 `accept`、`recv` 和 `send` 调用。
- 处理 `send` 的部分发送结果，直到整个缓冲区写完。
- 将 `recv() == 0` 视为对端有序关闭。
- 在成功和失败路径上都关闭每个拥有的描述符。
- 不要假设一次 `recv` 能返回一条完整消息。

## 故障排查

- **客户端无法连接。**检查服务器打印的端点，并确认服务器仍在运行。使用 IPv4 地址字面量 `127.0.0.1` 和实际绑定的端口；如果服务器以端口 0 启动，应连接它打印的已分配端口，而不是 0。
- **第一次 CLI 交互正常，但第二次无法连接。**检查提供的 `main`：它只调用一次 `serve_one`，并在该客户端关闭写入方向后退出。第二次 CLI 客户端交互前，重新启动 `./build/tcp-echo server 8080`；每次客户端调用都会建立一个新连接。
- **消息发送后，双方都在等待。**检查客户端的写入关闭和接收循环。发送后保留 `shutdown(socket_fd, SHUT_WR)`，并持续读取，直到 `recv` 返回 0；换行符不会结束这次字节流会话。
- **短文本正常，但二进制或大载荷被截断。**检查每次接收是否使用返回的字节数，包括其中嵌入的零字节；同时检查 `send_all` 是否在部分发送后继续推进。重新测试二进制数据和分段写入；不要将缓冲区当作以空字符结尾的字符串，也不要把一次接收当作完整载荷。
