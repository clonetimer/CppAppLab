# W9 · A5 解析器不变量与有界模糊测试

## 从这里开始

1. 阅读已验收的 A4 准入接口和 `include/admission_invariants.hpp`，理解输入字节与观察结果的关系。
2. 只修改 `src/admission_invariants.cpp`，实现观察结果检查器及等价比较，不重新写一个 HTTP 解析器。
3. 先验证一个正确接受结果，再验证固定测试构造的不一致结果。
4. 构建、运行测试并正式验收，然后可选择在自己的已保存源码上执行真实 Clang/libFuzzer 专项。
5. 阅读实际执行次数、覆盖统计与可能生成的复现输入。没有发现问题不等于不存在问题。

## 目标

学习本地解析器的属性验证、确定性语料回归，以及 ASan/UBSan 支持的有界覆盖引导模糊测试。复用已验收 A1/A4 解析链。所有输入都是本地内存字节，目标不建立网络连接、不接触外部服务或真实账号。

## 你的任务

只编辑 `src/admission_invariants.cpp`，实现 validate_observation 与 same_observation，接口由平台固定。测试刻意构造不一致观察，以证明检查器不能永远返回 None。

| 顺序 | 观察结果合同 |
|---|---|
| 1 | 未知状态返回 UnknownStatus |
| 2 | 待接收/拒绝时必须无消耗且无部分请求，否则 HiddenState；强制关闭必须与拒绝状态相符，否则 ClosePolicy |
| 3 | 已接受状态不应要求策略强制关闭 |
| 4 | 消耗量必须为正、不得超过输入和线长预算，否则 ConsumedBoundary |
| 5 | 方法和目标非空，版本合法，HTTP/1.1 Host 非空，否则 RequestShape |
| 6 | 消耗前缀内存在完整头部结束符且头部符合预算，否则 HeaderBoundary |
| 7 | 字段数量、解码正文长度及正文相对线长符合预算，否则 ResourceBudget |
| 8 | 其余返回 None |

比较状态、消耗字节、关闭策略和全部请求字段；无序头部映射的插入顺序不是语义。平台固定驱动在相同输入上重放 A4，对已接受消息检查准确消耗前缀以及少一个字节的前缀。这只验证选择的不变量，不能代替完整协议验证。

## 解释你的设计

为什么永远返回 None 的检查器会让模糊测试失去意义？为什么固定测试需要构造错误观察？如何判断完整和部分消息？为什么一万次执行没有发现错误仍不能证明程序不存在缺陷？

## 故障排查

- 不一致观察的测试失败：按规定优先级判断具体违规，不要只返回 None。
- 相同头部却被判不等价：比较映射内容而非遍历顺序。
- 可选编译器或运行库缺失：安装独立工具链并重新验证，不把普通单测当作真实 fuzz。
- 专项产生崩溃文件：保留实际复现与日志，在同一配置本地重放，缩小触发输入后再修正代码；不向外部服务发送任何输入。
