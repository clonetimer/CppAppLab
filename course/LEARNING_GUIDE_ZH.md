# CppAppLab 中文学习导航（W1–W9）

这是一份**学习路线图**。你不需要记住 24 个任务编号，也不需要一次读完所有技术文档。已经打开网页工作台时，先从首页的「继续学习」进入课程，遇到不会的地方再看提示。

网页顶栏的 **中文学习指南** 可以随时打开本页；首页也有 **第一次使用？先看四步说明** 入口。用上方的「第一次使用」「常用词解释」「学习路线」「常见错误」直接定位，点击「关闭指南」或按 Esc 返回原来的课程与文件。查看指南时，当前代码和学习进度会保留。

## 第一次使用：先完成一个最小任务

如果你以前没有写过 C++，先不要阅读后面的 W1–W9 技术路线。只做下面四步：

1. 在首页点击 **继续学习**，进入第一关。
2. 点击 **开始学习**，让工作台创建代码工作区。
3. 打开 `src/main.cpp`，把程序改成输出 `Hello, CppAppLab!`，并在末尾换行，例如 `std::cout << "Hello, CppAppLab!\n";`。先不要改其他文件。
4. 点击 **构建**，再点击 **运行程序**，最后点击 **正式验收**。后续工程课程对应的运行按钮会显示为「运行课程测试」。

三个按钮不是一回事：

| 按钮 | 它做什么 | 你应该看什么 |
|---|---|---|
| 构建 | 把 C++ 源码翻译成可运行程序 | 有没有编译错误 |
| 运行程序 / 运行课程测试 | 实际启动程序或课程测试 | 输出是否符合预期 |
| 正式验收 | 按课程固定标准检查并记录结果 | 是否显示 PASS |

**第一次遇到红色错误很正常。** 不要一次改很多地方：先看第一条错误，确认文件名和行号，再改一个问题。仍然不懂时，先点「提示 1」；还需要帮助，再看「提示 2」和「提示 3」。

如果你不知道某个词的意思，先看本页后面的「常用词解释」。不需要在开始前学会所有术语。

## 中断后继续学习

打开课程和文件后，可以把当前页面保存为浏览器书签。刷新这个页面会回到相同的课程与文件；重新从首页打开工作台时，可以点击带课程名称的 **返回上次**。在课程间切换后，浏览器的后退、前进也可以返回先前课程。程序正在运行、验收或保存失败时，工作台会先保留当前代码，待操作完成或保存成功后再切换。

关闭或刷新前，请等代码区显示 **已保存到本地工作区**。记住学习位置不等于备份尚未保存的源码。若暂时读不到工作区，教材仍可阅读，点击 **重试打开工作区** 即可重新读取；原有前置任务要求仍然有效。

增强编辑器加载较慢时，可以点击 **立即使用基础编辑器**；加载超过 8 秒也会自动回退。基础编辑器同样支持编辑、保存、构建、运行和正式验收。教材表格比屏幕宽时，可在表格内横向滚动查看完整列。

## 运行错误分支时看什么

有些课程要求程序对无效输入返回错误。例如计算器的 `divide 1 0` 应输出 `error: division by zero`，学习者程序按设计以状态码 3 退出。看到 **程序返回非零状态** 时，先对照教材核对输入与输出；这可能是正确的错误分支，也可能需要修复。普通应用运行不会添加正式验收记录，完成后仍需点击 **正式验收**。

## 常用词解释

- **源码（source code）**：你在编辑器里写的 C++ 文本，例如 `main.cpp`。
- **工作区（workspace）**：本关专用的文件夹；你修改的是工作区里的文件，不是平台的参考答案。
- **构建（build）**：把源码编译、链接成程序的过程。
- **运行（run）**：启动程序，观察它实际做了什么。
- **测试（test）**：用预先准备的输入检查程序行为是否正确。
- **正式验收（check）**：平台按固定课程标准检查，并保存这次结果。
- **提示（hint）**：逐级给线索，不会替你完成代码。
- **源码指纹（source fingerprint）**：平台用来识别本次验收对应哪一版代码的标记。代码改过后，旧 PASS 需要重新验收。
- **前置任务（prerequisite）**：必须先完成的课程；未通过时，后续任务会显示未解锁。

## 先弄清四件事

1. **目标是什么？** 每一关都有一个可见结果，例如打印一行文字、保存待办事项，或让 HTTP 请求得到正确响应。
2. **我该改哪里？** 进入任务后，程序会列出当前需要修改的文件。先只改这些文件，其他文件用于理解接口和参考。
3. **怎样知道做对了？** 运行任务中给出的验收命令，结果为 PASS 才算当前源码通过。验收由平台固定测试控制，不是你自行修改测试标准。
4. **失败怎么办？** 先读错误摘要，再请求 1～3 级提示。修改代码后重新验收；上一次 PASS 在源码改变后可能变成 STALE（待重新验证）。

## 从哪里开始

### 已经在网页工作台里

首页的「继续学习」会打开当前适合学习的课程。阅读开头的目标与操作说明，再点击「开始 / 继续学习」创建或恢复代码工作区。**源代码写在工作区，不是写在课程说明或平台的参考实现中。** 在网页里使用课程按钮即可完成编辑、构建、运行和正式验收。

也可以打开本指南的「学习路线」，点击课程名称查看对应讲解；未解锁的课程可以先阅读，开始任务仍需完成前置课程。从指南切换课程前，工作台会先保存当前修改；如果保存失败，课程和代码会保留，并在指南中说明原因。

### 使用命令行时

根据交付形式，选择对应启动命令；这两个命令行入口功能相同：

- **源码构建版本**：在仓库根目录运行 `./build/cppapplab`。
- **解压的学习者包**：在解压目录运行 `./cppapplab`。

在命令行菜单选择「继续学习」，程序会自动选择尚未完成、前置条件已满足的任务，并创建独立工作区。菜单中的「中文学习导航」或 `guide` 命令也能阅读本指南。教程中个别 `./build/cppapplab` 示例针对源码构建版本；使用解压学习包时，以任务页面底部自动给出的完整命令为准。

完成一个任务通常只需循环以下动作：

1. 阅读本关的「Goal / Your task（目标与要求）」与「Acceptance（通过条件）」。
2. 修改列出的工作区源码文件；一次解决一个小问题。
3. 网页中点击提示或「正式验收」；命令行中运行程序给出的 `hint` 或 `check` 命令（保留引号中的工作区路径）。
4. 如果失败，优先看第一个编译错误或测试失败，再逐级查看提示。
5. 验收 PASS 后继续下一关；重新运行「继续学习」会保留已有进度。

**任务状态读法：** AVAILABLE＝可开始，LOCKED＝前置任务未通过，IN PROGRESS＝已开始，NEEDS WORK＝上次验收失败，PASSED＝当前源码已通过，STALE＝改过代码需重验。

## 按阶段学习：先有结果，再理解原理

### W1｜第一行 C++ 到多文件程序（2 关）

- **w1.hello-world · First C++ Program**：区分「写源码 → 编译 → 运行 → 比对输出」。只修改 `src/main.cpp`；看是否严格输出 `Hello, CppAppLab!` 且末尾换行。常见错误是多出提示词、漏换行或输出到错误流。
- **w1.calculator · Multi-file Calculator**：理解头文件是接口、`.cpp` 是实现、`main` 是调用者。实现四则运算与除零错误返回；重点是错误分支也有确定行为，不只看正常算式。

### W2｜用 STL 保存数据（1 关）

- **w2.todo-cli · Persistent Todo CLI**：用 `vector` 管理条目、用文件让下一次运行仍能读到数据。先让添加和列表工作，再完成标记、删除、文件转义和坏文件处理。关键自检：读取失败不能清空已有有效数据。

### W3｜把数据组织成类（1 关）

- **w3.task-manager · Task / TaskManager Refactor**：理解对象与所有权。把 W2 的数据管理封装成类，用 RAII 和 `unique_ptr` 管理生命周期；复制要独立，移动要转移所有权，旧数据文件仍能读取。

### W4｜让质量检查成为习惯（1 关）

- **w4.quality-gate · TaskManager Quality Gate**：练习写测试、调试和复现实验。先在普通 Debug 构建中定位失败，再理解 GoogleTest/CTest、GDB、Sanitizer 与静态分析各自检查什么。重点是能解释一个失败，而不是只追求绿色输出。

### W5｜开始接触 Linux 系统调用（1 关）

- **w5.system-lab · Linux System Programming Lab**：使用已提供的有界线程安全队列，并实现通过 `pipe/fork/exec/waitpid` 执行外部程序的过程控制。重点观察：队列关闭后谁会被唤醒？子进程超时后是否被回收？

### W6｜并发任务调度（1 关）

- **w6.thread-pool · Thread Pool and Futures**：把多个工作线程组织成有界线程池。先写任务提交和 `future` 结果，再处理异常传播、背压（队列满时不能无限增长）和安全停机；特别留意提交与关闭同时发生的情况。

### W7｜从单连接走向多客户端（2 关）

- **w7.tcp-echo · TCP Echo Server and Client**：学习 `socket/connect/accept/send/recv`。TCP 是字节流，一次接收不保证一条完整消息；用二进制和较大消息验证字节没有丢失。
- **w7.tcp-chat · Multi-client TCP Chat with epoll**：把单客户端升级成事件驱动聊天室。重点理解注册昵称、消息广播、粘包/拆包、`EAGAIN` 与待发送缓冲区；慢客户端不能拖垮其他连接。

### W8｜逐层构造 HTTP 服务（11 关）

先看它们的依赖顺序，不要从最后的压测任务直接开始。

1. **w8.http-protocol**：HTTP 请求行、响应行、头部、CRLF、`Content-Length`；分清字节数与字符数。
2. **w8.http-parser**：增量解析 TCP 输入；不完整数据应等待，真正非法数据才报错。
3. **w8.static-files**：静态文件与响应；重点是路径检查、正确状态码和文件内容。
4. **w8.router**：按方法与路径分配处理器；区分路由未找到与方法不允许。
5. **w8.http-server**：组合 `epoll`、线程池和 HTTP；先保证正确收发，再考虑并发性能。
6. **w8.http-connection-policy**：根据 HTTP 版本与 `Connection` 头决定是否复用连接。这一关只做策略，不提前改服务端生命周期。
7. **w8.http-keep-alive**：同一 TCP 连接按顺序处理多个请求；确保响应顺序正确。
8. **w8.http-connection-guards**：连接超时与配额限制；解释为什么空闲连接不能一直占用资源。
9. **w8.http-graceful-shutdown**：停止接收新请求并排空已有任务；学习有序退出。
10. **w8.http-observability**：日志与指标；用可观察证据解释服务器发生了什么。
11. **w8.http-operational-load**：并发客户端、慢读端、持续 Keep-Alive 和重复启动停止；重点验证资源回收，不把一次压测速度当作产品吞吐承诺。

### W9｜安全的 HTTP 输入与文件边界（4 关）

- **w9.http-chunked**：解析分块传输。重点是十六进制块长度、分段接收、零长度结束块和 trailer；不能让 `Transfer-Encoding` 与 `Content-Length` 同时决定正文边界。
- **w9.request-target**：严格解析请求目标和查询参数。重点是百分号解码只做一次，保留重复查询键，并拒绝路径穿越和非法控制字符。
- **w9.static-root**：基于已打开的目录描述符访问静态文件，用 `openat` / `O_NOFOLLOW` 阻止符号链接绕过根目录。重点理解「检查路径字符串」不等于「安全打开文件」。

- **w9.http-hardening**：在已有 A1 解析器上实现请求准入策略，限制头部、字段、正文与单条请求字节预算，保证未完成或拒绝时不消耗字节、不暴露部分请求。此关是本地内存练习，不是已部署的安全服务器。

**课程边界：** 当前课程目录包含 24 个任务（A4 为本轮新增候选，验收见项目状态）。W9-A5 和 W10–W12 仍是路线图内容。此导航不代替每关完整教材和固定验收规则。

## 常见错误：先定位，后修改

每关教材的 **Troubleshooting（故障排查）** 会列出这关容易遇到的现象、应检查的位置和下一步动作。先找到与你的失败现象相近的一条，再回到对应文件或测试；不要一次改动多个模块。

网页工作台提供「从这里开始」「故障排查」「验收要求」三个章节入口。开始课程后，教材中可打开的文件路径会变成按钮，点击即可在代码区查看。标有「只读」的头文件来自课程提供的接口，可以阅读和复制；实现代码仍在可编辑的源文件中完成。

浏览器的「提示 1、2、3」与命令行的三级提示提供相同内容。先看提示 1，需要更多线索再继续。部分课程的提示 3 按主题分成小节，可以只读当前问题对应的小节。查看提示不会替你修改代码，也不会改变正式验收结果。

长提示可以在提示区域内滚动阅读，点击「返回讲解」回到教材。代码区的下一步说明会根据当前状态提示构建、运行、排错或正式验收；正式通过后会出现下一课的名称和继续按钮。修改已通过的源码后，工作台会刷新课程依赖及已打开的历史摘要，原有历史 PASS 仍保留，但当前源码需要重新验收。

| 看到的现象 | 先检查什么 |
|---|---|
| `error: expected ...`、缺少分号 | 编译器报出的**第一个**源文件和行号；先修语法，再看后续报错 |
| `undefined reference` | 函数是否只有声明、没有实现；对应 `.cpp` 是否被正确编译链接 |
| `No such file or directory` | 正在使用**仓库根目录**还是**学习工作区**；命令中的路径是否保留双引号 |
| `Result: FAIL`，但本地能运行 | 检查平台固定契约：错误分支、边界值、换行、状态码和资源释放 |
| `NEEDS WORK` | 读最近一次验收的错误摘要和完整日志，再用 `hint` 逐级求助 |
| `STALE` | 代码在 PASS 后改变；这是提醒重新验收，而不是丢失了源码 |
| `LOCKED` | 按提示先完成前置任务并取得当前 PASS |
| 运行的是旧程序 | 明确你在运行仓库的 `./build/cppapplab`，还是学习包的 `./cppapplab`；不要混用二者 |

最后提醒：固定验收只能证明当前定义的任务契约通过。读懂设计取舍、能解释关键边界和失败原因，才代表真正掌握本关。
