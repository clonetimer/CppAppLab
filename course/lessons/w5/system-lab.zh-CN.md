# W5 · Linux 系统编程实验

## 从这里开始

先从一个进程入手，不必一开始就学习整个 Linux API。

1. 阅读 `src/main.cpp` 中固定的 CLI，找出启动子进程的命令。
2. 跟踪数据路径：命令参数 → `run_process` → 子进程 → 捕获的输出和退出状态。
3. 先试用提供的有界队列：压入一个条目，再弹出它。
4. 先运行针对队列的专项测试，再添加并发生产者和消费者。
5. 使用固定的参数向量实现进程执行，然后添加超时、输出限制和子进程清理。
6. 最后测试无效输入、超时和输出截断。

**可以这样理解：**文件描述符是进程持有的一个小整数句柄。`fork` 创建子进程；`exec` 替换子进程运行的程序；`waitpid` 收集其退出状态。先跟踪一个子进程的完整生命周期，再学习管道和进程组。


## 目标

基于两个可复用组件，构建一个小型 Linux 命令运行器：

1. 有界、线程安全的生产者/消费者队列
2. 能捕获输出并报告进程终止情况的 POSIX 子进程运行器

本周将 C++ 并发库与真实的 Linux 内核接口联系起来。验收环境为 WSL2 + Ubuntu 22.04 或 24.04 + GCC；本任务专门面向 POSIX/Linux。

## 你的实现

在 `src/process_runner.cpp` 中实现描述符 I/O 和子进程管理，并完成 `tests/system_lab_test.cpp` 中的十个 TODO 测试。

`include/bounded_queue.hpp` 中的有界队列模板已提供。阅读它的实现，并在测试中验证其生产者/消费者行为。

`src/main.cpp` 中的 CLI 已提供。公共 API 声明在 `include/process_runner.hpp` 中。

## A 部分 — 有界队列

提供的队列使用固定容量、一个互斥量、两个条件变量和一个双端队列。

必须满足的语义：

- 队列满时，`push(value)` 等待。
- 队列空时，`pop()` 等待。
- `close()` 是幂等操作，并唤醒所有被阻塞的生产者和消费者。
- 关闭后拒绝新的压入操作。
- 关闭后，已入队的条目仍可取出。
- 队列已关闭且已取空时，`pop()` 返回 `std::nullopt`。
- 不使用忙等循环；使用带谓词的条件变量等待重载。
- 所有共享状态由同一个互斥量保护。

容量为零的队列可以作为有效对象存在，但不能接收或返回条目。

## B 部分 — POSIX 子进程运行器

使用 Linux/POSIX API 实现 `write_all` 和 `run_process`。

进程运行器必须：

- 验证参数向量、超时和输出上限
- 创建管道，并通过 fork 创建子进程
- 在两个进程中都关闭未使用的管道描述符
- 将子进程的 stdout 和 stderr 都重定向到管道
- 使用参数向量调用 `execvp`；不要拼接 shell 命令字符串
- 在父进程中读取输出，并重试被中断的系统调用
- 限制保存的输出大小，同时继续读空管道
- 使用 `waitpid` 收集子进程的终止状态
- 超过截止时间时，终止并回收子进程
- 区分正常退出与信号终止

输出上限用于限制内存占用；不能因为达到上限就让父进程停止读取管道，否则仍在写入的子进程可能陷入死锁。

## 构建与运行

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure

./build/system-lab /bin/echo "hello from child"
./build/system-lab /bin/sh -c 'exit 6'
```

第二个示例返回子进程的退出状态。进程运行器本身不会调用 shell；示例中的 shell 是调用者明确选择的子程序。

## 并发模型

使用带谓词的等待，不要在没有条件变量的情况下循环检查队列状态。谓词条件为：

- 当队列已关闭或还有剩余容量时，生产者可以继续
- 当队列已关闭或包含条目时，消费者可以继续

关闭操作必须通知两个条件变量，避免被阻塞的生产者或消费者在关闭后仍然休眠。

## 解释你的设计

1. 为什么每个进程都必须关闭自己不使用的管道端？
2. 为什么达到输出上限后，父进程仍需继续读空管道？
3. 为什么 argv 向量比拼接 shell 命令字符串更安全，也更便于组合？
4. 为什么条件变量等待应该使用谓词？
5. 队列关闭时，被阻塞的生产者和消费者必须发生什么变化？
6. 为什么终止超时子进程后，父进程还必须调用 waitpid？

## 故障排查

- **队列测试一直等待。**检查是否在其他线程有机会推进之前，就向满队列压入条目，或从空队列弹出条目。安排生产者或消费者解除等待；关闭时调用 `close`，确认两类等待线程都被唤醒，同时已入队的条目仍能取出。
- **echo 命令没有输出，并且以失败状态退出。**检查 `src/process_runner.cpp` 中的 `run_process`：初始代码返回空的 `ProcessResult`。先跟踪一个 `/bin/echo` 子进程的执行、输出捕获和退出状态收集，再添加超时用例。
- **子进程已经退出，但父进程始终看不到管道 EOF。**检查通过 `fork` 继承的每个管道描述符，尤其是父进程持有的写端副本。在两个进程中都关闭未使用的管道端，然后继续读空管道，并使用 `waitpid` 回收子进程。
- **大量输出或超时导致验收卡住。**分别检查输出上限和截止时间的处理路径。达到上限时必须停止保存字节，但不能停止读取；超过截止时间时必须终止并回收子进程。分别让这两条路径正常工作后，再重试有界输出和超时用例。
