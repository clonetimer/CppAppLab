## 提示 1

不要把十个失败测试替换成空函数体。每个测试都应该证明一项可观察的约定。从最小的“准备—执行—断言”结构开始，同时断言返回结果和执行后的状态。

## 提示 2

使用公共 API，不要直接访问私有成员：

- 使用 `Task::id()`、`title()` 和 `completed()` 观察值
- 使用 `TaskManager::find()` 进行不取得所有权的查找
- 使用 `snapshot()` 获取有序的值副本
- 使用 `size()` 和 `empty()` 检查集合状态

拷贝和移动测试既要比较对象地址，也要比较值。值相等并不能证明所有权相互独立。

## 提示 3

将各项诊断分开进行：

1. 使用 `--gtest_filter` 运行一个 GoogleTest 用例。
2. 使用 GDB 检查失败时的状态和调用栈。
3. 通过 CTest 运行普通 Debug 测试套件。
4. 在独立目录中进行 ASan/UBSan 构建。
5. 以仅检查模式运行 clang-format。
6. 在另一个构建目录中启用 clang-tidy。
7. 安装了 Valgrind 时运行它，并记录准确的命令。

不要仅为消除测试失败而修改期望值。解释这个测试要保护的不变量。
